Cette page dit quelles données l'application Terrariums et le serveur Exotic World traitent, pour quoi faire, où, et pendant combien de temps. Le code source de l'application, du socle et du serveur est publié sur GitHub : vous pouvez y vérifier ce qui suit. Read this page in English.

Responsable

L'éditeur de l'application, présenté dans les mentions légales, est responsable des données que traite le serveur Exotic World. Pour toute question ou demande : à compléter (adresse de contact).

Sur le serveur Exotic World, avec votre compte

Quand vous vous connectez avec votre adresse e-mail, l'application passe par le serveur de l'éditeur (exotic-world.duckdns.org), que vos socles rejoignent aussi. Il enregistre :

  • votre compte : adresse e-mail, clés publiques de vos clés d'accès (avec leur nom et leurs dates d'usage), empreinte d'un mot de passe s'il y en a un, préférences (carnet du mois par e-mail, noms donnés à vos socles) ;
  • vos sessions, sous forme d'empreintes, et vos abonnements aux notifications : l'adresse technique fournie par votre navigateur, avec ce qu'il dit de lui-même (nom, version, système) ;
  • vos socles : ceux qui sont rattachés à votre compte et ceux que vous partagez, avec les comptes invités et leurs droits ;
  • l'historique de vos socles : températures et consignes de chaque zone, un point par minute, et ce que chaque socle a vécu (connexions, défauts, redémarrages, mises à jour) ;
  • l'assistance : les rapports de diagnostic que vous envoyez, vos demandes au support, leurs réponses et les notes de l'équipe ; pendant un accès au socle que vous ouvrez au support, la clé temporaire de cet accès et ce qui y est fait ;
  • un journal d'audit des actions sur les comptes et les socles, où les adresses sont remplacées par une référence pseudonyme.

Le code d'appairage de vos socles reste sur votre téléphone : les commandes partent signées avec lui. Il n'est transmis qu'une fois au serveur, quand vous rattachez un socle à votre compte, pour que le serveur vérifie auprès du socle que vous le connaissez ; le serveur ne le garde pas. Le code de connexion reçu par e-mail n'est gardé qu'en mémoire, sous forme d'empreinte. Pour freiner les attaques, le serveur compte en mémoire, sur un quart d'heure, les tentatives de chaque adresse IP ; il n'enregistre pas les adresses IP.

Pour quoi faire

  • Vous rendre le service demandé : connexion, pilotage et historique de vos socles, notifications, partage, assistance, et carnet du mois si vous l'activez. Base légale : l'exécution du service que vous avez demandé (article 6, 1, b du RGPD).
  • Protéger le service : journal d'audit, limitation des tentatives, sauvegardes. Base légale : l'intérêt légitime de l'éditeur à sécuriser le service et à pouvoir rendre compte de ce qui a été fait (article 6, 1, f).

Aucune donnée n'est vendue, ni utilisée pour de la publicité ou du profilage.

Combien de temps

  • Compte, socles rattachés, préférences, abonnements, demandes au support : jusqu'à la suppression du compte.
  • Sessions : 30 jours sans usage. Code de connexion : 10 minutes.
  • Historique et événements des socles : 400 jours.
  • Rapports de diagnostic et journal d'audit : 12 mois.
  • Accès au socle ouvert au support : 24 heures par défaut, 7 jours au plus ; sa clé est effacée à la fin.
  • Sauvegardes : une par nuit, gardée 14 jours sur le serveur et 30 jours dans l'espace de stockage de Google Cloud. Une donnée effacée en disparaît donc au plus tard 30 jours après.

Supprimer votre compte efface aussitôt le compte, ses sessions, ses clés d'accès, ses abonnements, ses demandes au support et ses rapports, ainsi que l'historique des socles qui n'ont plus d'autre propriétaire.

Où, et chez qui

  • Google Cloud (contrat avec Google Cloud France SARL) héberge le serveur et ses sauvegardes, dans un centre de données de Google en Caroline du Sud, aux États-Unis.
  • Brevo (Sendinblue SAS, Paris) envoie les e-mails : codes de connexion, et carnet du mois si vous l'activez. Il reçoit votre adresse et le contenu du message.
  • Le service de notification de votre navigateur (Google, Apple, Mozilla ou Microsoft) achemine les notifications. Elles sont chiffrées : il n'en lit pas le contenu.
  • Netlify (États-Unis) héberge le site. Il garde les journaux techniques habituels d'un serveur web : adresse IP, page demandée, date.

Vos données sortent donc de l'Union européenne. Ces transferts s'appuient sur les garanties prévues par ces prestataires : les clauses contractuelles types de la Commission européenne et, pour les entreprises certifiées, le cadre de protection des données UE–États-Unis.

Sans compte, avec votre propre broker

L'application peut aussi parler directement à un broker MQTT de votre choix (réglage avancé). Le serveur Exotic World n'intervient alors pas : les messages entre vos socles et l'application passent par ce broker, selon ses propres conditions. Ils contiennent les températures, les consignes, les commandes et l'identifiant de chaque socle.

Sur votre appareil

L'application garde dans le stockage local du navigateur l'adresse du serveur ou du broker, votre session (ou l'identifiant et le mot de passe du broker), vos socles avec leur code d'appairage, vos préférences, et les températures reçues pour tracer les courbes. Désinstaller l'application ou effacer les données du site les supprime. Avec un code de verrouillage, cette configuration est chiffrée par ce code (AES-256), qui n'est enregistré nulle part. Le site ne pose aucun cookie et n'embarque ni traceur, ni publicité, ni mesure d'audience, ni script tiers. Le rapport de diagnostic n'est produit que si vous le demandez ; il ne contient ni mot de passe ni code d'appairage.

Le socle lui-même

Le socle enregistre son historique de températures et son journal dans sa propre mémoire. S'il est configuré pour envoyer des alertes ou un signal de vie vers une adresse web (webhook, ntfy, healthchecks…), ces messages partent vers le service que vous avez indiqué et contiennent l'identifiant du socle, les températures et le texte de l'alerte. Lors d'une mise à jour « depuis GitHub », le socle télécharge le binaire sur les serveurs de GitHub, qui voient son adresse IP. Pour les mises à jour automatiques, il y lit aussi, une fois par jour, un petit fichier décrivant la dernière version publiée : la requête ne contient rien d'autre que ce qu'un navigateur envoie (adresse IP, « terrarium/<version> » comme logiciel), ni identifiant ni température. Couper les mises à jour automatiques n'arrête pas cette lecture, qui sert aussi à vous prévenir ; elle cesse avec un firmware compilé sans manifeste.

Vos droits

Vous pouvez accéder à vos données, les faire rectifier ou effacer, en limiter l'usage, vous opposer à un traitement fondé sur l'intérêt légitime, et les récupérer dans un format lisible. Dans l'application, Réglages → Ton compte → Mes données permet d'exporter tout votre compte (fichier JSON) et de le supprimer. Pour le reste, y compris les notes du support et les lignes du journal d'audit qui vous concernent : à compléter (adresse de contact). Vous pouvez aussi adresser une réclamation à la CNIL (cnil.fr).
