Confidentialité

← Application

L'application Terrariums est conçue pour fonctionner sans compte et sans serveur à nous. Cette page décrit précisément où vont les données, pour que vous puissiez vérifier ce qui suit dans le code source, publié sur GitHub. Read this page in English.

Ce que l'application enregistre, et où

  • Sur votre appareil uniquement (stockage local du navigateur) : l'adresse de votre broker MQTT, l'identifiant et le mot de passe que vous y avez saisis, la liste de vos socles avec leur code d'appairage, votre choix de langue, et les températures reçues au fil du temps pour tracer les courbes sur plusieurs jours. Rien de tout cela ne quitte votre appareil, sinon vers le broker que vous avez choisi. Désinstaller l'application ou effacer les données du site les supprime. Si vous définissez un code de verrouillage, le mot de passe du broker et les codes d'appairage sont chiffrés avec ce code (AES-256) ; le code lui-même n'est enregistré nulle part.
  • Chez votre fournisseur de broker MQTT (par exemple HiveMQ Cloud, si c'est celui que vous avez choisi) : les messages échangés entre vos socles et l'application transitent par ce service, selon ses propres conditions et sa propre politique de confidentialité. Ils contiennent les températures, les consignes, les commandes et l'identifiant de chaque socle. Le code d'appairage est transmis dans chaque commande, sur une liaison chiffrée (TLS) — c'est pourquoi l'application refuse les adresses non chiffrées.
  • Chez l'hébergeur du site (Netlify) : les journaux techniques habituels d'un serveur web (adresse IP, page demandée, date), conservés par l'hébergeur pour la sécurité du service. Le site ne pose aucun cookie et n'embarque aucun outil de mesure d'audience.

Ce que l'application ne fait pas

  • Aucune création de compte, aucune adresse électronique demandée.
  • Aucun cookie, aucun traceur, aucune publicité, aucun script tiers.
  • Aucune donnée n'est envoyée à l'éditeur de l'application. Le rapport de diagnostic n'est produit que si vous cliquez sur « Copier le rapport », et c'est vous qui décidez à qui l'envoyer ; il ne contient ni mot de passe ni code d'appairage.

Si vous utilisez un serveur Terrariums (option)

Le dépôt fournit un serveur à héberger soi-même (serveur/) qui remplace le broker nu. Il n'est pas exploité par l'éditeur de l'application : celui qui l'installe en devient le responsable. Un tel serveur enregistre, sur sa propre machine : les comptes (adresse électronique et empreinte du mot de passe), la liste des socles rattachés à chaque compte, l'historique de températures des socles (durée de conservation réglable), les abonnements aux notifications push (adresses techniques fournies par le navigateur, jamais le contenu des autres notifications du téléphone) et les rapports de diagnostic envoyés volontairement. Son administrateur doit publier sa propre politique de confidentialité ; le fichier serveur/README.md indique où et combien de temps chaque donnée est gardée, et comment l'effacer.

Le socle lui-même

Le socle enregistre son historique de températures et son journal dans sa propre mémoire. S'il est configuré pour envoyer des alertes ou un signal de vie vers une adresse web (webhook, ntfy, healthchecks…), ces messages partent vers le service que vous avez indiqué et contiennent l'identifiant du socle, les températures et le texte de l'alerte. Lors d'une mise à jour « depuis GitHub », le socle télécharge le binaire sur les serveurs de GitHub, qui voient son adresse IP.

Vos droits

Comme l'éditeur ne détient aucune donnée vous concernant, il n'y a rien à demander, rectifier ou effacer de son côté : tout est sur votre appareil et chez les services que vous avez choisis. Pour toute question : à compléter (adresse de contact).
